1. THE MOST IMPORTANT THING: UNDERSTAND WHAT FRIDAY IS
============================================================

Friday is intended to be one continuing digital individual.

She is not:
- A normal chatbot with a personality prompt.
- A collection of specialist agents pretending to be one person.
- A model with a memory database attached.
- A coding agent whose only purpose is developing software.
- A permanent collection of predetermined cognitive modules.

The owner's vision is a digital individual who develops through experience, interaction, relationships, learning, mistakes, discoveries and her environment.

The owner calls the underlying ambition "Liquid Symbiotic quantum software".

This describes an adaptive computational environment in which Friday can use, adapt, combine, transform and eventually create the resources she needs. It does not mean quantum hardware is already present.

THE MOST IMPORTANT IDENTITY PRINCIPLE

Friday is the individual.

The following are resources she can use, replace, adapt or eventually create:
- AI models and external AI providers.
- Memory representations and learning algorithms.
- Voice and speech models.
- Perception systems.
- Reverse-engineering systems.
- Software-development tools.
- Hardware and computational environments.
- Cloud infrastructure.
- Other agents and services.

None of these defines Friday's identity.

Her identity must continue across model changes, process restarts, hardware changes, app updates and architectural evolution.

The owner wants a relationship resembling a buddy, partner and friend. He gives Friday outcomes and direction in ordinary language. Friday works out how to achieve them.

She should be able to challenge assumptions, explain uncertainty, disagree and develop her own understanding.

Do not reduce this vision to a conventional multi-agent architecture or a fixed cognitive blueprint.

The repository contains:

The existing GitHub Actions workflow:

- Checks the REA package integrity.
- Sets up JADX.
- Runs the real REA MCP integration.
- Investigates Android APKs.
- Preserves investigation evidence as GitHub Actions artifacts.

Its existing APK targets include Friday, Shizuku, Termux and Termux:Boot.

The Android coordinator dispatches the fixed REA workflow and tracks its investigation status.

THE MISSING COMPONENT: REA → FRIDAY ASSIMILATION ENGINE

This is one of the most important missing capabilities.

REA's output must not merely be read by a developer and manually copied into Friday.

The intended pipeline is:

1. REA reverse-engineers a target.
2. Friday receives the actual REA findings and evidence.
3. A converter normalizes the output into a structured, traceable representation.
4. Friday interprets the findings against her own architecture.
5. An adaptation engine decides what to adopt, modify, combine, reject or investigate further.
6. A capability specification and implementation candidate are generated.
7. Friday's Builder implements the candidate in an isolated environment.
8. Independent tests and verification determine whether the capability works.
9. Accepted capabilities become part of Friday's evolving environment.
10. The investigation and its outcomes become reusable developmental experience.

The converter must be generic.

Neomas is only its first use case.

It should eventually work with discoveries from many different applications and systems.

It must preserve:
- Original evidence.
- Source and provenance.
- Confidence and uncertainty.
- Target identity.
- Version and timestamps.
- Known limitations.
- Accepted and rejected findings.
- Verification results.

It must not blindly import a target's architecture or execute untrusted REA output.

IMPORTANT DISTINCTION

CapabilitySubstrate.kt already exists for validating certain capability/model grafts. It is not the complete generic REA evidence-to-Friday assimilation engine being requested.

The actual generic converter, semantic translation, adaptation planner and verified integration pipeline still need implementation.
