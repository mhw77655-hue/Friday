# JARVIS DEVELOPMENT ENTRYPOINT

Before performing any substantial work in this repository:

1. Read the Jarvis Vault roadmap and architecture documents.
2. Treat the Vault roadmap as the authoritative project specification.
3. Follow the existing architecture instead of inventing parallel systems.
4. Inspect the existing repository before modifying anything.
5. Reuse existing subsystems, contracts, capabilities, memory, execution, events, and infrastructure whenever they already exist.
6. Do not replace existing architecture with generic agent-framework architecture.
7. Do not create duplicate systems when an existing Jarvis subsystem already provides the required mechanism.
8. Keep changes aligned with the roadmap and record important architectural decisions.

The complete Building, Experimentation, Deployment, and Evolution specification is stored inside the Vault.

Read the relevant Vault Markdown documents before implementation.

If the task concerns the Building System, read the complete Building System roadmap first.

If the task concerns Jarvis architecture generally, read the Master Mechanism / Continuity specification first.

Do not treat this file as the complete architecture. It is the entrypoint to the authoritative Vault documentation.
