Two tools, honest read on each — neither is a "yes, use this now" the way OmniRoute's combo feature was; one is a cautionary reference, the other is redundant with what you already have.
Herdr — not useful to adopt, but genuinely useful as a warning. Its core mechanism is: no real status API from most agents, so it takes a screen snapshot, pattern-matches it against remote-fetched text patterns, and if nothing matches, it silently defaults to "idle" — even if the agent is actually stuck. That's the exact failure mode your own ralph.sh already avoids on purpose: it doesn't guess status from text, it independently re-runs the real verifyCommand and only trusts an actual pass/fail exit code — that's why the "LIE DETECTED" auto-reject step exists. Worth filing as confirmation your approach is more reliable than this genre of tool, not something to import. The one real idea in it — one agent hands work to another, waits, reads the result back — is exactly what claude-squad (already in the audit, Bucket A) does properly with real process/branch isolation instead of screen-scraping. Nothing new to add here.
9Router — same category as your own OmniRoute, not a new capability. Multi-provider routing, auto-fallback chains ("combos"), free-tier pooling, token compression — this is the same idea OmniRoute already gives you, arguably with more polish in this video's UI. Not worth switching or adding as a second router; that's added complexity and a second thing to maintain for no new capability. The one thing worth double-checking against your own OmniRoute setup: whether it already has an equivalent to 9Router's token-compression feature (20-65% claimed savings) — if not, that's the one line item worth pursuing, not the whole tool.
For JARVIS itself (not just the builder): Herdr's failure mode is the actual useful data point for Stage 12 (Nervous System Federation) later — when JARVIS eventually coordinates multiple sub-agents/organs, the lesson is don't build status detection on screen-text pattern matching with silent-fail-to-idle. Use explicit structured status reporting (real return codes, real state, like ralph.sh already does) — cheap to say now, but worth having on record before that stage gets designed for real.
