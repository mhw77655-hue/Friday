Straight answer: the fix isn't "shrink Galaxy Memory" — it's that the brain never does what the current plan almost does (compare every memory densely against every query). Both the neuroscience and the current 2026 SOTA converge on the same shape, and it's cheaper than plain dense-vector RAG, not more expensive.
The core insight, from both sides
The hippocampus doesn't store or compare rich content directly — it keeps a sparse, binary-ish index of pointers and lets a graph-like associative structure do the heavy lifting (hippocampal indexing theory). The 2026 AI line that directly copies this — HippoRAG — beats plain dense-vector RAG on multi-hop recall precisely by doing the same thing: build a sparse knowledge graph, use dense embeddings only to light up the right entry points, then let graph traversal (Personalized PageRank) do the actual multi-hop retrieval instead of comparing the query against every stored vector. That's less compute per query, not more.
Three concrete changes to fold into the existing Stage 02 design (same six stories, no redesign):

EMBEDDING-PROVIDER → quantize. Don't store float32 vectors. Binary-quantize to 1 bit/dimension (sign-bit only), compared via Hamming distance — pure bitwise XOR+popcount, no float math, no GPU/NPU dependency. This is a ~32x memory cut (a 768-dim float32 vector is ~3KB; binary-quantized it's ~96 bytes) with only 5-10% recall loss, and that loss barely matters once the graph does multi-hop reasoning anyway. This isn't a compromise — it's literally how sparse distributed memory (Kanerva's model of the brain's own associative memory, from the same neuroscience lineage) already works: retrieval by proximity in Hamming space is the brain-native operation, not a lesser substitute for it.
BLENDED-RETRIEVAL → make graph traversal primary, vectors just the trigger. Right now the plan treats vector similarity and graph traversal as two ranked signals blended together. Change it: dense/binary vector match only decides which graph nodes activate first; PageRank-style spreading activation across the bi-temporal graph does the actual multi-hop retrieval from there. Cheaper (no full-corpus vector scan every query) and matches how hippocampal indexing actually works.
Embedding model itself → pick a real small one, not a generic placeholder. EmbeddingGemma (308M) is MTEB-competitive and phone-sized — worth pointing Universal Research at it by name instead of leaving "small dedicated embedding model" undefined in the story.

What stays exactly as designed — already correct: bi-temporal supersession-not-deletion, salience/valence decay, and the CONSOLIDATION-DAEMON's idle-cycle episodic→semantic promotion. That last one is independently validated by the wake-sleep/complementary-learning-systems research — interleaved offline replay from a fast store into a slow store is exactly the real consolidation mechanism, not something to second-guess.
Net effect: same ambition, same six stories, but the resource-heavy part (dense float vectors compared against everything) gets replaced by the part that was always going to be cheaper and more brain-accurate.
