# Historical research corpus rules

**Status: archival and non-authoritative.** This directory contains material inherited from earlier Jarvis/Friday experiments. It is preserved only as historical evidence and a source of potentially reusable algorithms. It is not the current product, architecture, build system, roadmap, or instruction authority.

1. The canonical product is Friday in the Android application under `mobile/app`, with application ID and Kotlin namespace `ai.friday.assistant`.
2. The sole active delivery authority is `.ralph/FRIDAY_DELIVERY_PLAN.md`, subordinate to the owner's latest authenticated direction.
3. Nothing in this vault may define live app destinations, package names, endpoints, permissions, runtime assumptions, production wiring, or product capability claims.
4. Do not execute, build, install, or wire a vaulted project merely because its source exists here.
5. Preserve raw research provenance and licensing. Do not modify downloaded archives without an explicit reason.
6. When extracting a useful mechanism, document the algorithm, evidence, licence, limitations, Android portability, resource cost, and a Friday-native integration proposal in current `docs/` or `research/` documentation.
7. A donor becomes a production capability only after it is independently implemented or deliberately integrated, connected to the real production composition, covered by meaningful tests, and verified on the relevant host. A class name, source file, CI compile, or research note is not proof of operation.
8. Historical names such as Jarvis, prototype app IDs, old server addresses, and superseded architecture descriptions are not current product instructions.
9. If historical material conflicts with current Friday source or owner intent, the current owner instruction and active delivery plan win.

The vault is retained to avoid destroying potentially valuable historical algorithms and owner research. It must never be mistaken for the live Friday implementation.
