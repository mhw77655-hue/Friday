# Friday Research Corpus Rules

**Status:** repository research policy. This file supersedes the legacy Jarvis-era corpus rules.

## Authority and identity

1. Friday is the only active product identity. The canonical Android application ID and Kotlin namespace are `ai.friday.assistant`.
2. The sole active product authority is `.ralph/FRIDAY_DELIVERY_PLAN.md`, governed by `governance/repository_truth.json` and the owner-authored vision records.
3. This `vault/` tree is historical research and evidence. Files named `JARVIS_*`, old milestone reports, old design bibles, and prior agent logs describe superseded project states. They are not current instructions, production architecture, endpoint configuration, package identity, or capability evidence.
4. Historical owner statements may be preserved for provenance. They do not override the owner's latest authenticated direction or the active Friday plan.
5. Raw downloaded archives and source snapshots are evidence, not dependencies. Do not install or copy a repository merely because it exists here.

## How to reuse research

1. Extract the underlying algorithm, data structure, protocol, benchmark method, or engineering insight—not the donor project's architecture, identity, package names, endpoints, or assumptions.
2. Verify licensing, provenance, security, platform compatibility, and measurable benefit before adoption.
3. Re-express accepted mechanisms behind Friday-owned contracts and integrate them through Friday's actual Android production composition.
4. Label every retained implementation as production, optional, experimental, test-only, or archived. A file, class, test double, dependency, document, or graph node is not proof of a live capability.
5. Require production wiring and the relevant integration/device evidence before promoting a capability claim.
6. Keep donor-specific code in clearly named research/archive locations unless it has passed review and is deliberately adapted into the Friday production source tree.
7. Never allow this corpus to redefine Friday's identity, authority, permissions, signing trust, continuity, recovery, or release process.

## Cleanup rule

Preserve historically useful owner evidence and reusable research where it has provenance and a clear archival label. Remove empty trash, stale active instructions, dead production destinations, and disconnected implementations. Do not delete useful research merely to make the repository look smaller; quarantine it so it cannot be mistaken for the live product.
